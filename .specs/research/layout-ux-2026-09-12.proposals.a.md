# Explorer A proposals — Layout panel UI/UX (information-architecture / provenance leans)

Context: `.specs/research/layout-ux-context.md`. NOTE: generated in-session after subagent quota failures; independence degraded vs the ToT ideal.

---

## A1 — Provenance chips + dead-knob collapse (incremental disclosure)

**Summary:** Keep today's form, but every parameter row gets a provenance chip (`uff data` / `preset` / `custom`), and dimensions fully owned by importer data collapse into a read-only capsule with an "override" affordance.

The smallest change that fixes the measured defect: the panel keeps its current structure (engine picker, presets, physics sliders, cooling, halt, backend, seed), but each row carries a small right-aligned provenance label. When `TYPED_FORCE_SUMMARY` reports full coverage of a dimension (25/25 bonds typed), the `spring_len` slider is replaced by a one-line capsule: `25/25 rests from UFF · override ▸`. Clicking "override" converts the capsule into the slider (and marks it `custom`), making the dead-knob state unrepresentable: you cannot believe you're tuning bond lengths when the data owns them. The misleading "sliders scale on top" banner is replaced by the per-row chips, which state the truth locally instead of globally and falsely.

Key decisions: (1) provenance is per-row, not per-panel — global banners are where the lie lived; (2) collapse only at full coverage; partial coverage (e.g. 12/25 bonds) shows the slider with a `12/25 from UFF` chip — it governs the remainder, which is true; (3) overrides are explicit user actions, recorded as `custom` so persistence semantics stay unchanged. Trade-offs: keeps all current knobs visible (still constant-centric, still vault-flavored naming); doesn't solve unit-scale absurdity (repulsion 535 on ångström geometry stays confusing, just labeled); minimal implementation risk. **Probability 0.85. Complexity low.** Risks: chip noise in a 340px panel; users never discover "override"; regime auto-selection still missing (molecule without `?config` still boots vault-tuned values, now merely labeled as such).

## A2 — Engine / Regime / Intent three-band restructure

**Summary:** Rebuild the panel as three bands: engine picker (algorithm), an auto-resolved named Regime capsule (base parameters + provenance), and 2–4 dimensionless Intent sliders (Spread, Stiffness, Settle) that multiply the regime base; raw constants demoted to an Advanced disclosure with provenance chips.

The panel's unit of thought changes from "physics constant" to "what do you want the layout to do". The Regime band is resolved automatically from graph class + size + typed data: `Molecular · UFF — 24 atoms, 25 bonds`, `Vault · 10.2k nodes`, `Generated · grid 12×12`. It names what today is invisible state (`for_n_nodes` result, `?config` preset, typed-data presence) and makes it switchable (Fast/Balanced/Pretty/Molecular/Custom). Intent sliders are multipliers on the regime base, so they compose with typed data instead of colliding: Spread scales UFF geometry for a molecule and spring_len+repulsion for a vault; Stiffness is spring_k; Settle packages cooling/damping/energy-halt. Advanced contains today's constants with A1's provenance chips and dead-knob collapse.

Key decisions: (1) regime auto-resolution is the correctness fix as well as the UX fix — the molecule boots into a molecular regime without requiring `?config=`; (2) intents are dimensionless multipliers, never absolute constants, so unit mismatches are unrepresentable; (3) constants remain reachable (Advanced) — no capability loss, no engine change (intents write through into the existing GpuForceOptions). Trade-offs: medium implementation cost (regime resolver + intent mapping + panel restructure); intent→constant mapping needs per-regime definitions (small table, config-not-code); two concepts to learn (regime, intent). **Probability 0.80. Complexity medium.** Risks: intent mappings feel mushy to power users; regime auto-resolution misfires on hybrid graphs (partially typed); "Custom" proliferation if users tweak one constant and lose regime semantics.

## A3 — Layer accordion (Data / Regime / You)

**Summary:** One panel, three stacked sections matching the three parameter layers exactly — "From the data" (read-only), "Regime" (preset picker), "Your adjustments" (the only editable section) — with exactly one section expanded at a time.

The information architecture mirrors the mental model 1:1 instead of inventing new concepts. "From the data" lists what the importer owns (25 bond rests, 24 weights, authored 3D kept) as read-only rows with source links (node/edge type tables). "Regime" is a radio list of named presets with one-line descriptions (Vault n-tuned defaults, Molecular UFF, Fast/Balanced/Pretty, config presets). "Your adjustments" holds the constants — but only the ones the upper layers leave meaningful (data-owned dimensions don't render). The accordion enforces "one action per screen": you configure one layer at a time, top-down, and the collapsed headers summarize their contents (`Regime: Molecular · UFF`, `You: 2 overrides`).

Key decisions: (1) the layer model is taught spatially (top = highest precedence); (2) "Your adjustments" is the only mutable surface — provenance is structural, not labeled; (3) override count in the collapsed "You" header makes hidden state glanceable. Trade-offs: accordion hides two-thirds of the panel at any time (discoverability cost); editing a data-owned value requires an explicit "override" hop into "You" (friction by design, but friction); doesn't rename the vault-flavored constants. **Probability 0.80. Complexity low.** Risks: accordion collapse/expand gymnastics in a 340px panel; users who live in "You" never see regime changes; summary-line design is easy to get wrong (stale counts).

## A4 — Provenance spreadsheet (one table, Source column, override toggles)

**Summary:** Replace the form with a single compact table of every parameter — rows: name, effective value, source (`uff`/`preset`/`default`/`you`), and a toggle to override — making the full parameter space and its ownership visible at once.

Every parameter the engine resolves becomes a row: `rest length (edge 7) 1.43 · uff`, `repulsion 0.02 · preset`, `gravity 0 · you`. Data-owned rows are read-only until their toggle flips; regime rows reset with regime change; "you" rows persist. A filter row scopes by dimension (bonds/repulsion/integration). This is the maximal-transparency end of the spectrum: nothing is hidden, and the table itself is the explanation. For molecules the "rest length" rows could be grouped (25 rows → one group row with distribution summary) to stay within panel height.

Key decisions: (1) total visibility over progressive disclosure; (2) override as a per-row toggle with reversion (toggle off = back to data/preset value); (3) grouping for high-cardinality typed rows. Trade-offs: table density fights the 340–480px panel; tabular UI reads as engineering console, not Operate-mode calm; editing model is uniform but semantically flat — no guidance about what matters. **Probability 0.08. Complexity medium.** Risks: overwhelming for vault users (dozens of rows); grouping/summary design is its own project; per-row persistence semantics get fiddly across graph reloads.

## A5 — Task-flow wizard (one action per screen)

**Summary:** The panel becomes a short flow: ① pick engine → ② confirm the detected regime → ③ adjust at most two intents — with the full settings surface available only via a "tune" escape hatch.

Impeccable's "one action per screen" taken literally. On graph load the panel shows step ② pre-answered (`Detected: Molecular · UFF — keep? [yes] [switch]`), then step ③ with two sliders chosen per regime (molecule: Spread, Stiffness; vault: Spread, Settle). Steady state collapses to a summary card (`gpu-force · Molecular · UFF · 2 custom`) with Edit re-entering the flow. The full constant form survives only inside "tune", framed as an expert surface with provenance chips.

Key decisions: (1) optimize the common path (accept the detected regime, nudge one intent) over the full surface; (2) flow state is transient — steady state is the summary card, not the wizard; (3) per-regime intent choice keeps the wizard honest about applicability. Trade-offs: flow framing adds ceremony to what is often a one-slider visit; power users route around it permanently (two UIs to maintain); step model fights the dockable-panel idiom (panels are ambient, not modal). **Probability 0.06. Complexity medium.** Risks: wizard fatigue; duplicate maintenance of flow vs tune surface; ambient panel conventions violated (users expect panels to be stable state, not flows).

## A6 — Layout shrinks to engine + regime; parameters move to Inspector

**Summary:** The Layout panel keeps only engine selection, regime capsule, and run controls (solve/wake/pause); all parameter editing moves to the Inspector panel, contextual to whatever is selected (graph, node, edge).

Selection-driven parameter editing: select nothing → Inspector shows global layout parameters (with provenance); select an edge → its rest length (UFF value, override field); select a node → its repulsion weight. This exploits the existing panel ecology instead of growing the Layout panel: parameters live next to the thing they parameterize. The Layout panel becomes purely operational (what runs, on what base, start/stop) — Operate mode — and the Inspector becomes the Read/Edit surface.

Key decisions: (1) contextual editing beats global forms for data-owned parameters (per-edge rests are naturally per-edge); (2) Layout panel minimalism is the goal, not a casualty; (3) Inspector's existing document/attribute structure absorbs parameters as another tab. Trade-offs: global parameters (gravity, cooling) have no natural selection context ("nothing selected" is a weak home); splits one mental task across two panels; Inspector is already loaded (document editing, node meta). **Probability 0.05. Complexity medium.** Risks: parameter discoverability collapses (users must know to select an edge); two panels must stay in sync; remote engines' settings have no selection analog at all.
